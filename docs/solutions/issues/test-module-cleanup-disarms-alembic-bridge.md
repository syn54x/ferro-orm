## Problem

This run failed (16 tests, both dialects) while every file passed alone:

```
pytest tests/test_migrate_baseline.py tests/test_alembic_translator.py ...
```

The translator's autogenerated revisions were stock Alembic
(`op.create_table('tr533team', sa.Column(...))`, `sa.Enum(...)`), and the
refusal for a context without `ferro_options()` never fired.

## Cause

The per-test `isolated_imports` fixture deleted **every** module imported
during the test from `sys.modules`. The first Alembic test of the run
(`test_an_alembic_built_database_is_baselined_and_alembic_version_untouched`)
is where `alembic.autogenerate` and `ferro.migrations.alembic` were first
imported, so both were dropped afterwards. The process then held two copies:

- `ferro.migrations.alembic` stayed bound as an attribute of
  `ferro.migrations`, so `from ferro.migrations import ferro_options` kept
  returning the old module, whose comparator sits on the **old**
  `alembic.autogenerate.compare.comparators` dispatcher.
- The next `from alembic.autogenerate import produce_migrations` built a
  **new** `alembic.autogenerate.compare` with a fresh dispatcher that never saw
  `dispatch_for("schema")` from ferro.

Every later autogenerate ran Alembic's comparator alone.

## Takeaway

Module cleanup in tests drops only what the test imported **from its
temporary project** (`tests/conftest.py::imports_isolated_under`, the shared
`isolated_imports` fixture). Never delete library or ferro modules from
`sys.modules`: anything that registers into another module's state at import
time (dispatchers, registries) silently splits in two. Pinned by
`tests/test_isolated_imports.py`, which first-imports Alembic inside the
isolation in a fresh interpreter and asserts ferro's comparator still refuses
a context without `ferro_options()`.

## How to recognize

- **Symptom:** later tests in one process get stock Alembic ops for ferro's
  tables (`op.create_table(...)`, `sa.Enum(...)`, `op.create_foreign_key(...)`
  where the translated ops belong), or a refusal test reports
  `DID NOT RAISE RuntimeError`. It happens only when certain files run
  first, and every file passes on its own.
- **Tell:** the module in `sys.modules` is not the one bound on the package,
  or Alembic's compare module was imported a second time:

  ```python
  import sys, ferro.migrations
  sys.modules.get("ferro.migrations.alembic") is not ferro.migrations.alembic  # split
  ```

  A test that runs after the culprit sees a different
  `id(sys.modules["alembic.autogenerate.compare"])` than one that runs before.
- **Find the culprit:** bisect by putting each earlier file in front of the
  first failing test. Then look at that file's fixture teardown for a loop
  that deletes `set(sys.modules) - before` without checking where each module
  was loaded from.
