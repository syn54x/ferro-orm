# The generator diffs the DDL-bearing projection of the IR

A schema snapshot carries the whole modelset envelope, and some of it renders no DDL: Python-side defaults (ferro persists no server-side `DEFAULT`; the only one it writes is the transient backfill default on `ADD COLUMN`), back-references, and declaration metadata. We decided that the generator compares only the part of two snapshots that renders DDL, and that a difference outside it is **not a schema change**: `migrate new` reports "no schema change" and writes nothing, and the next real migration's snapshot carries the newer metadata. Otherwise every cosmetic model edit would produce an empty migration whose only content is a fresh `ir.json`. The projection grows with the emitter: the day ferro emits a persisted `DEFAULT`, defaults join it and a default change becomes a migration — the rule is "what renders DDL", not a fixed field list.
