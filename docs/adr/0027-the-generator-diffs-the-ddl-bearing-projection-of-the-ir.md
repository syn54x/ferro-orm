# The generator diffs the DDL-bearing projection of the IR

A schema snapshot carries the whole modelset envelope, and some of it renders no DDL: Python-side defaults (ferro persists no server-side `DEFAULT`; the only one it writes is the transient backfill default on `ADD COLUMN`), back-references, and declaration metadata. We decided that the generator compares only the part of two snapshots that renders DDL, and that a difference outside it is **not a schema change**: `migrate new` reports "no schema change" and writes nothing, and the next real migration's snapshot carries the newer metadata. Otherwise every cosmetic model edit would produce an empty migration whose only content is a fresh `ir.json`. The projection grows with the emitter: the day ferro emits a persisted `DEFAULT`, defaults join it and a default change becomes a migration — the rule is "what renders DDL", not a fixed field list.

Amended 2026-10-10 (#622): the live side may carry what the declared side cannot. The live read carries each column's server default, and a plan from a live database to a declared snapshot (drift, baseline, the reconciliation pass, the generated revision) plans a `DropDefault` op for every **foreign default**: a live default that is not one ferro itself leaves. Ferro's own are the serial key's sequence default, recognised by the sequence the column owns (`pg_get_serial_sequence`), never by a text match on `nextval`, and on SQLite ADR-0034's kept literal, told by shape (see that ADR's amendment). A plan between two declared snapshots never carries the op, so no generated file changes and this projection is untouched; the op is rendered by the one renderer (`ALTER TABLE … ALTER COLUMN … DROP DEFAULT`; a table rebuild on SQLite), run by the pass under `migrate_destructive` only (removal of what the model never declared, ADR-0013's ladder), written by the Alembic bridge as `alter_column(server_default=None)`, and its down is irreversible with its reason: there is no declared side to put a foreign default back from. Retiring a column or a label (ADR-0053) renders no DDL on an already-nullable column and is not a schema change under this rule.
